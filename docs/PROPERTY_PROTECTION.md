# Защита имущества и границ

Проверка исходников от 15.11.2026, после PR #64.

## Исправленные пути обхода

- **Воронка снаружи → сундук в привате:** `InventoryMoveItemEvent` ранее не проверялся.
  Теперь автоматический перенос блокируется в обе стороны границы привата и спавна,
  а также между разными приватами. Проверяются обе половины двойного сундука.
- **Вагонетка с воронкой, закатившаяся под чужой сундук:** извлечение из защищённого
  контейнера в мобильный инвентарь запрещено даже внутри одной территории. Иначе
  вагонетку можно было увезти вместе с добычей. Это ограничение действует также на
  собственные вагонетки: у автоматического переноса нет подтверждённого владельца.
- **Открытие транспорта с инвентарём:** проверка физических контейнеров раньше
  пропускала сущности. Теперь учитываются местоположение вагонетки, лодки с сундуком
  и других носителей инвентаря; для доступа требуется CONTAINERS.
- **Стойка для брони:** смена экипировки и урон не проверяли права привата. Теперь
  требуется BUILD, а урон без определённого игрока отменяется на защищённом участке.
  Отдельный обработчик не меняет PvP и не затрагивает других существ.
- **Кровать / дверь на границе:** проверялся только первый установленный блок.
  Теперь проверяются все заменённые блоки `BlockMultiPlaceEvent`; при отказе
  отменяется установка целиком.
- **Ведро:** место клика и соседний блок не всегда совпадают с изменяемым блоком
  (в том числе при заполнении блока водой). Проверяется `PlayerBucketEvent.getBlock()`;
  отмена выполняется на HIGHEST вместо MONITOR.

Обычные блоковые воронки внутри одного привата и в дикой местности работают.
Публичные права на контейнеры не разрешают автоматический перенос через границу:
у воронки нет игрока, по которому можно проверить доверие. Явный `loveclaims.bypass`
применяется к действиям игрока, но не снимает ограничений с автоматизации.
Клановые территории сохраняют запрет строительства; правила спавна используются
для действий игроков. Игровые меню и личные инвентари не считаются блоковыми сундуками.

## Проверка

Java 25, `mvn verify`: **75 тестов, без ошибок и пропусков**. Девять новых тестов
используют реальные классы событий Paper и моделируют перенос в обе стороны,
двойные сундуки, мобильные инвентари, оба ведра, многоблочную установку, экипировку
и повреждение стойки. Проверено сохранение разрешённой автоматизации, прав BUILD
и прежней обработки PvP.

Проверка на живом Paper/Purpur не выполнялась. Перед установкой в основной сервер
проверить эти сценарии на тестовом сервере с обычным игроком без bypass, затем
повторить с владельцем/участником. Нагрузочные измерения и профилирование памяти
в этот проход не входят; результаты не означают отсутствие других обходов.
